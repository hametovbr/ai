# Sol medium adaptation analysis

## Scope and decision

Analyzed all 36 backed-up skills, including the newly added OpenSpec orchestrator. Adapted 29 entrypoints and retained 7 unchanged. The originals remain byte-for-byte in `skills/`; the profile is a separately maintained derivative. This update changes repository copies, not the installed ChatGPT skills.

The working hypothesis is that explicit execution contracts and selective reference loading reduce unnecessary instruction burden at medium effort. Behavioral checks can reject a regression on a case; they cannot establish a general improvement in model capability. No blind model-name replacement, runtime/API configuration migration, or new model feature was introduced.

## Cross-file review corrections

- Reconciled Light/Standard/High review and authorization conditions in `resolve-ambiguous-tasks` entrypoint and references. An optional review cannot become mandatory just by following a link.
- Preserved ELI5's defining HTML visual deliverable; removed only the runtime-specific argument placeholder. An actual missing capability or explicit user format request controls fallback.
- Preserved explicit invocation through supported `agents/openai.yaml` policy; normalized unsupported frontmatter in the profile while retaining raw provenance.
- Removed an unsolicited voice-profiling scope restriction introduced during editing.
- Audited moved n8n guidance for redundant confirmations and unconditional mass-loading. Adjusted retired tool aliases and broken sibling routes; live instance schemas remain authoritative.
- Preserved detailed database material but made engine/workload evidence authoritative over universal index, migration and downtime claims.
- Clarified the n8n retry budget after a paired response left “cap delay” ambiguous: never shorten a valid Retry-After; defer or terminate explicitly when the budget cannot cover it. Retries share the request-rate budget. This is a disclosed post-case refinement.
- Updated one bundled validator: an unresolved `{named action}` is now rejected. Its review/authorization boundary is documented as semantic, not something the script proves.

## Validation and remaining limits

All 36 entrypoints passed the skill creator's validator. Existing source resource paths remain present; no raw snapshot mismatch or unresolved substantive local Markdown link was found. Fenced example links are not package dependencies. Licenses and attribution remain present.

The changed validator was executed against concrete valid/invalid fixtures; see [validator-results.json](evals/validator-results.json). Unchanged scripts were preserved; they were not re-executed against live systems. Behavioral evidence is in [RESULTS.md](evals/RESULTS.md), with exact responses and predeclared invariants.

The live official GPT-5.6 guidance was unavailable. Domain-specific n8n, database and other live services were not exercised. These edits optimize instruction structure and portability; external API correctness still requires each skill's existing live-documentation and runtime verification gates. No model-wide reliability, speed or quality gain is claimed.
