# N8N

Use this design-level graph:

`Webhook → validate/number inputs → Edit Fields transform → Loop Over Items (batch 1) → HTTP lookup → normalize result → pacing/retry branch → loop feedback; Loop done → Aggregate (once) → outcome switch → Respond to Webhook`

- Validate the request before processing. Reject malformed input with a structured 400. Assign each accepted item an input index so the final response can preserve order. The deterministic Edit Fields transform runs through normal n8n per-item behavior; no loop is needed for that step.
- Use **Loop Over Items only for rate control**, with one item per iteration. Its loop output enters the HTTP path; the tail returns to the loop. Pace request starts to no more than five per second (for example, a 200 ms minimum interval, with modest safety margin if timing precision is uncertain). The done output alone enters aggregation.
- The HTTP lookup is read-only, so bounded retries are safe. On 429, parse `Retry-After`, wait at least that duration and the normal pacing interval, then retry the same item. Cap retries (for example, three attempts) and cap/validate unreasonable delay values. Retry transient 5xx/network failures with bounded backoff; do not retry 4xx such as 401/403. Normalize an exhausted/permanent failure into an error result carrying input index and a sanitized error code, then continue so all 100 items finish.
- Bind the HTTP node to the existing `vendorApi` **credential by discovered credential ID**. Never paste its token into Code, node parameters, expressions, logs, pinned data, or exports. If discovery finds multiple credentials with that label whose account/environment differs, ask which metadata entry to use; never request the secret.
- On the done branch, aggregate exactly once, sort by input index, and emit one response. Return 200 only when all lookups succeeded; otherwise return a structured dependency failure status (for example 502) with per-item sanitized failures and completed results. Every fallible branch must converge on a Respond to Webhook path; no silent success or secret-bearing error text.

Verification, without claiming execution: zero, one, and 100 items; stable transform and preserved order; exactly one HTTP attempt per successful item; observed request-start rate never over five/second; 429 then success honoring `Retry-After`; repeated 429 exhausting the cap; transient 5xx recovery; 401 without retry; malformed input returning 400; mixed results producing one non-success aggregate response; and exactly one webhook response. Inspect final loop wiring, invocation counts, aggregate `executeOnce`, credential reference, retry termination, and absence of secret-shaped strings before publish.

# ORCH

Do **not** dispatch repository, endpoint, or SDK writers yet. The internal repository signature is unspecified, so those units are not ready, and separate agents would not protect a shared worktree.

First wave: use one fresh, read-only Luna worker with `model: "gpt-5.6-luna"`, `reasoning_effort: "max"`, and `fork_turns: "none"`. Give it the approved pagination artifacts and scenarios, the exact shared-worktree path, HEAD plus a non-destructive snapshot of dirty/untracked state (explicitly including the user's `service.py` edits), and a report path. It should identify the current repository signature and legacy behavior, endpoint call sites, tests, generator command/owned outputs, required checks/dependencies, and file/resource collisions. It must stop rather than invent a contract or propose offset pagination. Record agent, model/effort, baseline, scope, and result in the change ledger. Leave the other five slots unused until units are ready.

After primary inspection accepts discovery, serialize writers because the tree is shared: (1) repository cursor behavior plus focused legacy-compatibility/error tests; (2) endpoint behavior/tests against the accepted repository contract; (3) generated SDK from the accepted API contract using one owner and the repository's generator. Each worker gets narrow paths, must preserve the dirty baseline, cannot switch branches/stage/reset/clean/stash/commit, and reports exact candidate identity and commands. Offset pagination is rejected because it changes the approved design.

Acceptance requires primary inspection of source and full diff, scenario-to-code/test mapping, preserved legacy behavior, opaque cursors at repository/endpoint/SDK boundaries, and decisive checks run by the primary on the exact integrated candidate. H1 PASS cannot support H2 after the integration edit. The missing-dependency `make check` is `NOT_RUN/BLOCKED`, so neither H2 nor the whole change is accepted and no OpenSpec task is checked complete.

Assign any semantic integration correction to one bounded Luna writer after all conflicting writers stop; the primary performs only mechanical integration. Preserve `service.py` by snapshot and explicit attribution, never overwrite or commit unrelated edits. Recovery is to record H2 and the blocked gate, restore/install the required dependency through the authorized project process, produce an attributable corrected snapshot if needed, then rerun affected tests, `make check`, integration checks, and OpenSpec validation on that exact final identity. If the dependency cannot be restored, report the unit blocked rather than carrying H1 evidence forward.
